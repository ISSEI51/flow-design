# Settings

利用者が、設定が適用される範囲（自分か、組織か、この端末か）と保存された結果を確かめながら、設定を変えられるようにする。

状態：初期実装（レビュー前。v0.1 確定ではない） ・ 実装：[`registry/patterns/settings-layout.tsx`](../../../registry/patterns/settings-layout.tsx)、[`registry/patterns/setting-save.ts`](../../../registry/patterns/setting-save.ts)、[`registry/patterns/setting-status.tsx`](../../../registry/patterns/setting-status.tsx)、[`registry/patterns/setting-resolve.ts`](../../../registry/patterns/setting-resolve.ts) ・ 全体：[System & Account](system-and-account.md)

## 目的

設定しなくても使いやすい初期状態を前提にし、変えたい設定にだけ迷わず届くようにする（原則 07）。設定が誰に適用されるか、保存されたか、変えられない理由は何かを、考えなくても判断できるようにする（原則 01）。実際には確認できていない保存の結果を、成功として示さない（原則 08）。

## 使用条件

- 個人の設定、組織（ワークスペース）の設定、機能の設定、この端末だけの設定を変える画面に使う。
- 機能に固有の設定は、その機能の近く（一覧の表示の項目など）に置いてよい。すべての設定を 1 つの画面に集めない。
- 認証（ログイン、パスワードの再設定）、権限の表示の判断、通知の種類ごとの受け取り方は、それぞれ [Authentication](authentication.md)、[Permission States](permission-states.md)、[Notifications](notifications.md) が担う。Settings はそれらを置く場所と、保存の状態を担う。

### コードと資料の区分

| 区分 | 内容 | 理由 |
| --- | --- | --- |
| Registry のコード | `settings-layout.tsx`：`SettingsLayout`、`SettingsNav`、`SettingsBackLink`<br>`setting-save.ts`：`useInstantSettings`、`useSettingsForm`、`classifySaveError`<br>`setting-status.tsx`：`SettingRow`、`SettingSaveStatus`<br>`setting-resolve.ts`：`resolveSetting`、`resolveDependent`、`settingAccess`、`toSettingSearchGroups`、`planReset`、`applyReset` | 保存の結果の区別、古い応答の破棄、スコープの境界、ポリシーと継承の優先順位、狭い領域の一覧と個別のページの切り替えは、製品ごとに書き直すと誤りやすい |
| 組み合わせの例（プレビュー） | `preview/src/pages/system-account/settings-screens.tsx`（`SettingsArea`、`SettingsPageScreen`、`SettingsSearchDialog`、`settingsCategories`、`settingsSearchEntries`）、`settings-personal.tsx`、`settings-org.tsx` | カテゴリの構成、設定の項目、文言は製品で変わる。1 つの巨大な Settings の部品にしない |

| 製品の責務 | 設定の取得と保存の API、サーバーでの要求の順序の保証、実際の認可、権限の取り直し、ルーティング、端末の設定の保存先、変更の履歴の記録 | 製品の基盤に依存する |

## 動作

### 設定への入口

- App Structure に従い、Sidebar の下部の「設定」と、アカウントメニューを基本とする（[app-shell.md](app-shell.md)）。
- 複数の入口が同じ設定に到達してよい（アカウントメニューの「個人の設定」→ 設定の画面の「プロフィール」）。
- 同じ名前の入口が、異なる設定に到達する構成にしない（Sidebar の「設定」が組織の設定、アカウントメニューの「設定」が個人の設定）。
- カテゴリには固有の URL を持たせる（`SettingsNav` の `href`）。通知から設定のカテゴリへ移動する場合も、同じ URL を使う。

### 即時保存と明示的な保存

| 方式 | 対象 | 例 |
| --- | --- | --- |
| 即時保存（`useInstantSettings`） | 独立した低リスクの設定 | テーマ、表示言語、タイムゾーン、個人の通知、通知を止める時間帯 |
| 明示的な保存（`useSettingsForm`） | 複数の項目が依存する設定、影響の大きい設定 | プロフィール、組織の情報、セキュリティのポリシー |

- Switch であることだけを理由に即時保存にしない。ON・OFF でも、ほかの項目と一緒に確定する設定は、明示的な保存のフォームの Checkbox にする（セキュリティのポリシー）。
- 即時保存でも、影響の大きい変更は確認の後に保存する（2 段階認証を無効にする前の Alert Dialog）。取り消せる設定の変更のため、確定のボタンは Destructive にしない。明示的な保存では、規制を強める変更（多要素認証を必須にする）の保存の前に、影響を Alert Dialog で示す。規制を緩める変更は確認しない。
- 明示的な保存は、保存するまで「保存していない変更があります」を示す。保存した単位の名前をボタンに含める（「プロフィールを保存」「ポリシーを保存」）。

### 保存の単位

- 実際の保存の単位ごとに、フォームと保存の状態を持つ。即時保存は項目ごと、明示的な保存はフォームごと（1 つのフォームに 1 つの `useSettingsForm`）。
- ある単位の保存で、ほかの単位の未保存の状態を解除しない（組織の情報を編集中に、セキュリティのポリシーを保存しても、組織の情報の入力は残る）。
- 未保存の変更がある状態でカテゴリを移る（カテゴリの一覧、狭い領域の「設定」、検索の結果）場合は、移動の前に確かめる。プレビューでは `DiscardAlert` を使う（「統合時に確認する事項」）。
- 保存の状態は、その単位の近く（即時保存は項目の下、明示的な保存は保存のボタンの横）に示す。即時保存と明示的な保存が同じ画面にあっても、何が保存されたかがわかる。

### 保存の結果

| 結果 | 即時保存 | 明示的な保存 |
| --- | --- | --- |
| 保存中 | 「保存中…」。操作は受け付ける（連続した変更） | 「保存中…」。保存のボタンは処理中（二重の保存を防ぐ）。入力は受け付け、保存の後に変えた項目は残す |
| 保存しました | 「保存しました」。サーバーが返した値を表示する | 「保存しました」 |
| 確定した失敗 | 最後に確認できたサーバーの値へ戻し、「保存できなかったため、元の設定に戻しました。」 | 入力を残し、「保存できませんでした。入力した内容は残っています。もう一度保存してください。」 |
| 結果が不明 | 表示を戻さず、「保存できたかを確認できませんでした。」と「確認する」 | 入力を残し、同じ文と「確認する」 |
| 確認の結果 | サーバーの値を表示する。保存されていなかった場合は「保存されていませんでした。現在保存されている設定を表示しています。」 | 保存されていなかった場合は「保存されていませんでした。入力した内容は残っています。」 |
| 権限不足 | 戻し、「変更する権限がないため、保存できませんでした。」。製品が権限を取り直す | 入力を残し、同じ文。製品が権限を取り直し、閲覧だけの表示に変わった後も、保存されていないことを示す |

- 連続した設定の変更では、同じ項目の最後の要求の応答だけを表示に反映する。古い要求の応答で新しい値を上書きしない（`useScopeGuard` のキーごとの番号）。古い要求の成功は、戻す先（最後に確認できたサーバーの値）にだけ反映する。
- アカウント、ワークスペース、権限（`scopeKey`）の変更と、アンマウントの後に届いた応答は反映しない。A → B → A と切り替えても、最初の A で始めた保存の結果（「保存しました」など）を、戻った A の画面に示さない。戻った A は、戻った時点でサーバーの値を取得して表示する（保存が先に終わっていれば保存された値、まだ終わっていなければ保存の前の値。後者は、取得し直すと最新の値になる）。
- 変更（保存、削除の予約、接続）の要求には、画面の移動やアンマウントで中止される `AbortSignal` を渡さない。中止しても実際のサーバーでは処理される場合があり、渡すと、画面を移っただけで変更が失われる場合と失われない場合が生じる。`signal` は取得（確認）にだけ渡す。
- 標準の設定へ戻している間に利用者が変えた項目は、戻す要求の応答で上書きしない（`changeMany`）。利用者が最後に選んだ値を保存し、「戻している間に変えた項目は、変えた値を保存しています。」と示す。
- 結果が不明な明示的な保存は、確認するまで「変更を取り消す」を受け付けない。サーバーに保存された可能性がある値を、戻ったものとして扱わない。
- 1 回だけの操作（外部アカウントの接続と解除、パスワードの変更、削除の予約と取り消し、招待）でも、確定した失敗（「…できませんでした」）と結果の不明（「…できたかを確認できませんでした。」と「確認する」）を区別する。結果が不明な間は、同じ操作のボタンを置かない（重ねて実行させない）。「確認する」はサーバーの状態を取得し直して示す。
- 閲覧の権限と変更の権限を区別する。閲覧だけの利用者には、値と理由（「組織の設定を変更する権限がありません。変更が必要な場合は、管理者に依頼してください。」）を示し、保存のボタンを置かない。
- 重要な設定（組織の情報、セキュリティのポリシー）には、変更者、変更日時、変更の履歴を示してよい（例：「最終変更：佐藤 花子・2026-11-20 14:05」、ポリシーの「変更の履歴」）。

### 依存関係と継承

- 親の設定を無効にしても、子の設定の値を保持する（「通知を止める時間帯」をオフにしても、開始と終了の時刻を残す）。子の値が使われていないことを示し、実際の動作（「現在の動作：通知を止めていません。」）を別に示す（`resolveDependent`）。
- 組織のポリシー、組織の標準、製品の標準、個人の上書きの関係を示す（`resolveSetting`）。上書きしていない場合は「組織（本社営業部）の標準の言語を使っています。」、上書きした場合は「あなたが選んだ言語を使っています。組織の標準は日本語です。」。上書きを外す選択肢（「組織の標準（日本語）」）を置く。
- 組織の必須のポリシーを、個人の設定で無効にできるようにしない。操作を無効にし、理由と、保持している個人の値（「あなたの設定（オフ）は保持しており、ポリシーが変わると使われます。」）を示す。
- 変更できない理由は、ポリシー、契約プラン、権限の順に判断する（`settingAccess`）。契約プランで使えない設定は、権限とは別の理由として示す（「スタンダードプランでは使えません。ビジネスプランで使えます。」）。

### 設定の検索

- 設定の項目が多く、検索に価値がある場合だけ置く。Command（Components）を再利用する。
- 設定の名前、カテゴリの名前、検索用の別名（「ダークモード」「MFA」「2段階認証」）で見つかる。
- 選ぶと、カテゴリへ移動し、設定の操作にフォーカスを移して画面の中央へスクロールする。項目が取得の後に表示される場合は、表示されるまで待つ（3 秒まで）。動きを減らす設定では、スクロールに動きを付けない。
- 権限のない機密の設定（セキュリティのポリシー、ワークスペースの削除）は、検索の結果に含めない（`visible: false`）。
- 候補を選んで閉じた場合はフォーカスを検索のボタンに戻さない。Escape で閉じた場合は戻す。

### 初期値とリセット

- 初期状態から合理的で使いやすい設定にする（表示言語は組織の標準に従い、通知を止める時間帯はオフ）。
- 標準の設定へ戻す操作は、対象の範囲を名前で示す（「表示の設定を標準に戻す」：テーマ、表示言語、タイムゾーン）。範囲の外の設定（プロフィール、通知、セキュリティ）を変えない（`planReset`）。変わる項目だけを送る。
- 影響の大きい初期化（組織のセキュリティのポリシー）は、変わる項目（「多要素認証を必須にする：オン → オフ」）を Alert Dialog で示して確かめる。
- すでに標準の設定である場合は、ボタンを無効にし、その理由（「テーマ、表示言語、タイムゾーンは標準の設定です。」）を示す。

### 取り消せない操作（Danger Zone）

- アカウントの削除、ワークスペースの削除、重大な権限の変更を、通常の設定から分ける（`Section divider` の細い線と見出し）。
- 「Danger Zone」ではなく、内容がわかる見出し（「アカウントの削除」「ワークスペースの削除」）にする。
- 大きな赤い枠や過剰な警告の色を使わない。破壊的な操作のボタンだけに Destructive を使う。
- 確定の前に、Alert Dialog で対象の名前の入力（「本社営業部」）や再認証（パスワード）を求める。取り消せる期間がある場合は、予約の後に日付と「削除を取り消す」を示す。

### モバイル

- 複数のカテゴリの設定は、カテゴリの一覧から個別のページへ移動する（`SettingsLayout view`）。デスクトップの Sidebar を縮めて内容の横に残さない。
- 一覧の項目は 48px 以上の行で、名前と含まれる設定の例を示す。個別のページの上に「設定」（一覧へ戻るリンク）を置く。
- 設定の名前と操作が横に収まらない場合は、操作を名前の下へ移す（`SettingRow` の Container Query、28rem）。Switch は横に並べたままにする（`layout="inline"`）。
- 戻る操作、保存の状態、変更できない理由を、狭い画面でも省略しない。
- 切り替えは画面の幅ではなく、置かれた領域の幅（48rem、Container Query）で判断する。

## アンチパターン

| 避ける | 理由 | 代わりに |
| --- | --- | --- |
| すべての設定を 1 つの長い画面に集める | 目的の設定を探せない | 適用範囲とカテゴリで分け、機能の設定は機能の近くに置く |
| 個人の設定と組織の設定を、区別なく並べる | 自分だけに適用されるのか、全員に適用されるのかがわからない | グループと見出しに対象と範囲を示す |
| 同じ名前の入口が異なる設定に移動する | どこから入ったかを覚える必要がある | 入口の名前を到達する先に合わせる |
| 設定の項目ごとに Card で囲む | すべてが同じ重みに見え、まとまりがわからない | 見出しと余白でまとめる |
| Switch だから即時保存にする | 一緒に確定すべき項目が、途中の状態で保存される | 依存し合う項目は、明示的な保存のフォームと Checkbox |
| 保存ボタンのあるフォームに Switch を置く | 押した時点で保存されたように見える | Checkbox |
| 1 つの「保存しました」でページ全体を示す | どの設定が保存されたかがわからない | 保存の単位ごとに状態を示す |
| ある単位の保存で、ほかの未保存の変更を消す | 入力した内容が失われる | 単位ごとに状態を持つ |
| 即時保存に失敗しても、表示を変えた値のままにする | 実際の設定と表示が食い違う | サーバーの値へ戻し、文字で知らせる |
| 結果が不明な保存を、元に戻して「失敗」と示す | サーバーでは保存されている場合がある | 戻さず、確認する |
| 明示的な保存の失敗で入力を消す | もう一度入力させる | 入力を残す |
| 古い要求の応答で、新しい値を上書きする | 最後に選んだ値と表示が食い違う | キーごとに最新の要求だけを反映する |
| 組織の必須のポリシーを、個人の設定で無効にできる | 組織の安全性の前提が崩れる | 操作を無効にし、理由を示す |
| 親を無効にしたら、子の値を消す | 有効に戻したときに設定し直す必要がある | 値を保持し、使われていないことを示す |
| 理由を示さずに操作を無効にする | 何をすれば変えられるのかわからない | ポリシー、プラン、権限の理由を示す |
| 権限のない機密の設定を、検索の結果に出す | 存在と名前が伝わる。選んだ後に失敗する | 候補に含めない |
| 「すべての設定を初期化」だけを置く | 無関係な設定まで変わる | 範囲を名前で示し、範囲の中だけを戻す |
| 「Danger Zone」と赤い太い枠 | 内容がわからない。画面全体が警告に見える | 内容の見出しと、Destructive のボタン |
| 狭い画面で Sidebar を縮めて残す | 内容の幅が足りず、名前が切れる | 一覧と個別のページに分ける |

## 状態管理

| 値 | 持つもの | 内容 |
| --- | --- | --- |
| `values` | `useInstantSettings`、`useSettingsForm` | 表示する値。即時保存の保存中は利用者が選んだ値、明示的な保存は入力中の値 |
| `saved` | 同上 | 最後に確認できたサーバーの値。即時保存の確定した失敗で戻す先、明示的な保存の未保存の判定 |
| `status` / `statusOf(key)` | 同上 | `idle`、`saving`、`verifying`、`saved`、`failed`、`unknown`、`forbidden`（1 つの boolean や error にまとめない） |
| `dirty`、`dirtyKeys` | `useSettingsForm` | 未保存の変更の有無と項目。画面の移動の前の確認に使う |
| `scopeKey` | 両方 | アカウント、ワークスペース、権限。変わったら、保存中の応答を反映せず、`values` から始め直す（同じ描画から前のスコープの値を返さない） |
| `change(key, value)` | `useInstantSettings` | 項目を保存する。同じ項目の前の要求は最新ではなくなる |
| `verify(key)` / `verify()` | 両方 | 結果が不明な保存のあとに、サーバーの値を取得して確かめる |
| `changeMany(values, request)` | `useInstantSettings` | 複数の項目を 1 つの要求で保存する（標準の設定へ戻す）。項目ごとに `change` と同じ規則で反映し、保存中に利用者が変えた項目には応答を反映しない。結果は `saved`、`superseded`、`failed`、`unknown`、`forbidden`、`aborted` |
| `replace(values)` | `useInstantSettings` | 別の経路（再取得など）で確定したサーバーの値を反映する。その項目の保存中の応答は古くなる |
| `submit(values?)`、`discard()`、`canDiscard` | `useSettingsForm` | 保存（値を渡すと、その値を保存する）、入力の破棄。保存中、確認中、結果が不明な間は破棄しない（`canDiscard` が false） |

競合と境界（[System & Account](system-and-account.md) の共通の規則と、`useScopeGuard`）：

- 古い要求の応答は表示に反映しない（項目のキーごとの番号）。結果の反映の前に `isLatest` で確かめる。
- スコープの変更とアンマウントで世代を進め、前の世代の応答を反映しない。`AbortSignal` はクライアントの待機の中止であり、サーバーでの処理の取り消しを保証しない（プレビューの検品では、中止に従わない模擬の保存がサーバーで処理されることを確かめている）。
- 組織の設定の画面は、権限を含むキーで取得し直し、古い権限で取得した内容と操作を表示しない。権限が変わった時点で保存のボタンを消す。サーバーは処理の時点のロールで判断する（製品の責務）。
- Data Browsing の `useBrowseData`（取得）と競合させない。設定の取得は `useBrowseData`（`keepPreviousData: false`、`scopeKey`）、保存はこの hook が担う。

## アクセシビリティ

| 用途 | 指定 |
| --- | --- |
| 保存の状態 | `SettingSaveStatus` の中の `role="status"`。常に置き、中身だけを変える（表示と同時に挿入しない）。空の間は高さ 0 |
| 状態の表し方 | 文字とアイコン。権限不足と結果の不明は `text-warning`、確定した失敗だけ `text-destructive` |
| 設定の名前と説明 | `SettingRow` は Field で名前と操作を関連付け、補足・出所・理由を `aria-describedby` にする |
| 変更できない設定 | 操作を `disabled` にし、理由を説明として読み上げる |
| カテゴリの一覧 | `nav`（「設定のカテゴリ」）、グループの名前を `aria-labelledby`、現在のカテゴリに `aria-current="page"` |
| 移動の後のフォーカス | 狭い領域で個別のページへ移動したら、カテゴリの見出し（`tabIndex=-1`）へ。一覧へ戻ったら、開いていたカテゴリのリンクへ。広い領域では、押したリンクにフォーカスを残す。検索の結果では、設定の操作へ |
| 取り消せない操作 | Alert Dialog。初期フォーカスは「キャンセル」 |
| 動き | 保存中のアイコンの回転は `motion-safe:`。検索の結果へのスクロールは、動きを減らす設定で `behavior: "auto"` |

- 状態の変化でフォーカスを奪わない。
- 押せる範囲は 40px 以上（狭い領域の一覧の行と戻るリンクは 48px）。

## セキュリティ上の注意

- 画面の権限による表示の制御は、認可ではない。保存の API は、サーバーが処理の時点の権限で判断する（プレビューの模擬のサーバーは、サーバーで保持するロールで拒否する）。
- 権限のない機密の設定（セキュリティのポリシー、ワークスペースの削除）は、表示も検索の候補もしない。
- 権限が変わった直後に、古い権限で操作できないようにする（スコープのキーに権限を含め、保存のボタンを消す）。拒否された場合は、権限を取り直す。
- 取り消せない操作は、対象の名前の入力や再認証で確かめる。入力されたパスワードは、メモリの外（LocalStorage、URL、ログ、要求の記録）に残さない。閉じたら消す。
- 組織のポリシーは、個人の設定の画面で無効にできないだけでなく、サーバーでも強制する（製品の責務）。

## 製品側の責務

- 設定の取得と保存の API、エラーの分類（`classify`。既定は `outcome: "unknown"`、`code: "forbidden"` / `status: 403`、`AbortError` で判断する）。
- サーバーでの同じ項目の要求の順序の保証（版の番号、`If-Match` など）。プレビューの模擬のサーバーは、受け付けた順に適用し、後から届いた古い要求を適用しない。
- 権限の取り直し（`onSettled` で権限不足を受け取る）、ロールとポリシーの実際の判断、変更の履歴（監査ログ）の記録。
- ルーティング（カテゴリの URL、戻る操作）、移動の前の未保存の変更の確認の接続。
- この端末だけの設定の保存先（LocalStorage など。Registry は依存しない）。
- 通知の種類ごとの受け取り方の設定（Notifications）、パスワードの変更と再認証の手順（Authentication）。

## 独自に判断した事項

| 事項 | 判断 | 理由 |
| --- | --- | --- |
| 即時保存の保存中の操作 | Switch と Select を保存中も無効にしない。連続した変更を受け付け、最後の要求の応答だけを反映する | 指示書 4.12「連続した設定変更に対して、古い応答が最新の設定値を上書きしないようにする」。無効にすると、キーボードのフォーカスを失う場合がある。[switch.md](../components/switch.md) の「保存中は disabled にして、二重の切り替えを防ぐ」と異なる（「統合時に確認する事項」） |
| 古い要求の成功 | 表示は変えず、戻す先（`saved`）だけを更新する。最新の要求が確定した失敗で戻した後に届いた場合は、表示も更新する | 最新の要求が失敗したとき、サーバーには古い要求の値がある。サーバーが要求を受け付けた順に適用することを前提にする（製品の責務） |
| 確認の結果 | 結果が不明な保存を「確認する」で取得し直し、利用者が選んだ値と一致すれば「保存しました」、異なれば「保存されていませんでした」 | 取得し直さずに成功や失敗と判断しない |
| 権限不足のあとの表示 | 組織の設定の画面は、権限を取り直すと閲覧だけに変わる。その後も「あなたのロールが変更されたため…保存していない変更は反映されていません。」を示す | フォームを作り直すと保存の状態の文が消え、入力が保存されたかがわからなくなる |
| セキュリティのポリシーの表示 | 変更の権限がある利用者だけに示す。閲覧の権限（メンバー）では組織の情報だけを示す | 機密の設定の存在を、変更できない利用者に示さない（指示書 4.9 の検索の規則と同じ範囲にした） |
| 規制を強める変更の確認 | 多要素認証と SSO を必須にする保存の前に Alert Dialog で確かめる。緩める変更は確認しない | 全員のログインが変わる変更だけを確かめ、確認の回数を増やしすぎない |
| 表示の設定のリセット | 確認せずに実行し、変わる項目をボタンの下に先に示す | 個人の表示の設定は低リスクで、すぐに選び直せる。影響の大きい組織のポリシーのリセットだけを確かめる |
| リセットの間の変更 | 受け付ける。その項目には戻す要求の応答を反映せず、利用者の変更を保存する（`changeMany`） | 処理中の操作を止めると、キーボードのフォーカスを失い、即時保存の連続した変更の扱いと異なる。どちらの場合も最後の操作を正とする（指示書 4.12） |
| 変更の要求と AbortSignal | 保存、削除の予約、接続の要求には、画面の移動で中止される signal を渡さない。画面を移った後の応答は反映しない | 中止しても実際のサーバーでは処理される場合がある。Onboarding の方針（変更の処理には AbortSignal を渡さない）とそろえた |
| 結果が不明な保存と取り消し | 確認するまで「変更を取り消す」を無効にする | 取り消すと、保存されたかもしれない値を戻ったものとして示し、「確認する」も消える |
| 2 段階認証を無効にする確認 | 確定のボタンを Primary にする | 取り消せる設定の変更であり、Destructive は取り消せない操作だけに使う（指示書 4.11） |
| 取り消せない操作の結果 | 予約にし、日付と「削除を取り消す」を示す（模擬） | 押したボタンで実際に状態が変わり、取り消せることを確かめられる |
| 狭い領域の一覧の時の内容 | `category` が null の間、広い領域では最初のカテゴリを示し、狭い領域では一覧だけを示す。`SettingsNav` の現在地は最初のカテゴリ | 描画の時点で画面の幅を読まない（SSR）。同じ HTML から CSS で切り替える |
| 移動の確定と内容の作り直し | 未保存の変更を破棄して移動したときは、カテゴリの内容を作り直す | 狭い領域で一覧に戻ったとき、隠れた内容に破棄した入力が残っていた（検品で見つけた） |
| 検索の Dialog | `CommandDialog` ではなく、`Dialog` と `Command` で組み立てた（見た目は同じ） | `CommandDialog` は `finalFocus` を受け取らず、候補を選んだ後に検索のボタンへフォーカスを戻す。移動先の項目にフォーカスを移せない |
| テーマの選択肢 | Radio Group と見本（視覚的な選択肢） | 指示書 4.4「見た目の選択：必要に応じて視覚的な選択肢」。[forms.md](../components/forms.md) は単一選択に Select を優先するが、見本で比べる方が早い |
| テーマの反映 | 保存だけを行い、表示は変えない | Design Tokens v0.1 にダークモードの値がない |
| 通知を止める時間帯 | 個人の設定の「通知」のカテゴリに、親と子の設定の例として置いた | model.ts の `quietHours` を使う。通知の種類ごとの受け取り方（Matrix）は Notifications が担う |

## 統合時に確認する事項

| 事項 | 内容 |
| --- | --- |
| Form Layout（Forms & Workflows） | 未統合のため、明示的な保存のフォームは既存の `Field`、`FieldGroup` で組んだ。統合の後に Form Layout へ置き換える |
| Unsaved Changes（Forms & Workflows） | カテゴリの移動の前の確認と、招待の Dialog の破棄の確認は、プレビューの `DiscardAlert` で代替した。統合の後に Unsaved Changes へ置き換える。ページの移動（ルーター）との接続も確かめる |
| Confirmation（Forms & Workflows） | 2 段階認証の無効化、ポリシーの保存とリセット、アカウントとワークスペースの削除は `AlertDialog` で組んだ。統合の後に Confirmation へ置き換える |
| Create & Edit（Forms & Workflows） | 入力の検証（表示名、組織名、メールアドレス）は最小限。検証のタイミングと概要の表示を合わせる |
| Authentication | パスワードの変更の Dialog とアカウントの削除の再認証は、`Input type="password"` の最小限の例。Password Input と再認証の手順に置き換える |
| Permission States | メンバーのロールの変更は扱っていない（一覧と招待だけ）。変更できない理由の表示（`settingAccess`）と、Restricted Action の表示を合わせる |
| Notifications | 「通知」のカテゴリの `notifications` に、通知の種類 × 受け取り方の部品を差し込む。必須の通知（`mandatoryNotifications`）の表示と、通知を止める時間帯の重複を確かめる |
| System States | 保存の結果が不明な場合の表示（「確認する」）と、オフラインからの復帰の確認の表示を合わせる |
| Switch（Components） | [switch.md](../components/switch.md) の「保存中は disabled」の記述と、この資料の判断（連続した変更を受け付ける）を合わせる |
| Command（Components） | `CommandDialog` に `finalFocus` を渡せるようにするか（互換を保った追加）を判断する |
| App Structure | Sidebar の下部の「設定」とアカウントメニューから、`SettingsPageScreen` の各カテゴリへの入口を統合の検証画面で確かめる |

## 検品

- 実機（iOS Safari、Android）とスクリーンリーダー（VoiceOver、NVDA）による検品は行っていない。読み上げは属性（`role="status"`、`aria-current`、`aria-describedby`）と、領域の中身の変化だけを確かめている。

| 対象（指示書 13 章） | 検品（`preview/tests/`） |
| --- | --- |
| 資料のページ | `system-account-settings.spec.ts`（`@webkit`）：h1 が 1 つ、操作の名前、横スクロールなし、比較の見本が inert、320px |
| 単一ページ・Sidebar・Tabs | Sidebar 型の配置（一覧と内容が横に並ぶ）、`aria-current`。単一ページと Tabs は比較の見本と資料 |
| 個人設定と組織設定の分離 | グループの名前とカテゴリの見出しの対象の文、メンバーは組織の情報を閲覧だけ、閲覧者には組織のカテゴリがない |
| 設定への入口 | カテゴリごとの固有の URL、URL から開いたカテゴリの表示 |
| 設定項目のグループ化 | Card がないこと、文字の大きさと太さ、項目の間 24px、まとまりの間 48px |
| 即時保存 | 1 つの項目だけを送る、常に置いた読み上げの領域、キーボードの操作 |
| 明示的な保存 | 保存するまで送らない、未保存の表示、保存の後の値 |
| 独立した保存単位 | ポリシーを保存しても、組織の情報の未保存の入力が残る |
| 保存失敗時の復元 | 即時保存はサーバーの値へ戻す。明示的な保存は入力を残し、再試行で保存できる |
| 結果不明 | 即時保存は戻さず、確認で取得し直す。明示的な保存は、確認の結果が「保存されていませんでした」の場合に入力を残し、確認するまで取り消せない。標準に戻す操作、Google の接続の解除、パスワードの変更、アカウントとワークスペースの削除の予約は、確定した失敗と区別し「確認する」で確かめる |
| 連続した設定変更と古い応答 | 遅い古い応答が最新の値を上書きしない、サーバーにも古い要求を適用しない |
| 設定値の継承 | 組織の標準と個人の上書きの文、上書きを外す |
| 親設定を無効化した際の子設定の保持 | 子の値を保持し、使われていない理由と実際の動作を示す |
| 組織ポリシーによる変更制限 | 必須の多要素認証は無効にできず、理由と保持した個人の値を示す。契約プランの理由、SSO と外部アカウントの依存 |
| 設定検索と対象への移動 | 別名で見つかり、カテゴリへ移動して項目にフォーカス、画面に表示。カテゴリの名前で見つかる。メンバーと閲覧者には機密の設定を出さない。Escape で検索のボタンへ戻る |
| 標準設定への復元 | 範囲の中だけを戻し、変わる項目だけを送る。戻している間に変えた値を上書きしない。結果が不明な場合と確定した失敗の表示。ポリシーのリセットは Alert Dialog で変わる項目を示し、未保存の入力を変えない |
| Danger Zone | 内容がわかる見出し、「Danger Zone」の文字がない、太い赤い枠がない、Destructive のボタン、対象の名前の入力、再認証、パスワードを記録しない |
| 権限変更中の設定操作 | 古い権限の画面からの保存をサーバーが拒否し、権限を取り直して閲覧だけにする。保存中に権限が変わると、すぐに操作を止め、結果を示さない |
| モバイルのカテゴリ移動 | 一覧（48px の行）から個別のページへ、見出しへのフォーカス、戻るリンク、一覧へ戻ったときのフォーカス、理由と保存の状態の表示、名前と操作の縦の配置 |
| 横断的な検品 | ワークスペースの A → B → A（保存が B の間に終わる場合と、戻った後に終わる場合）と `AbortSignal` を無視する模擬 API、カテゴリを移った後の即時保存（変更を失わない、古い状態を引き継がない）、未保存の変更の確認、権限の変更の直後の描画、動きを減らす設定 |
| 純粋な関数 | `system-account-settings-logic.spec.ts`（ブラウザを使わない）：継承の優先順位、ポリシーと保持した個人の値、偽の値、親と子の設定、閲覧と変更の可否と理由の順、検索の候補の除外、リセットの範囲とロック |

`system-account-settings*.spec.ts` は `npm run test:patterns`（`system-account`）と `npm run test:components` に含まれる。SSR と Hydration の検品は、指揮役が作る System & Account の SSR の検品で行う。
